# ADR-0001: 联机架构——中转服务程序 + 守秘人浏览器为权威

## Status
Proposed

## Date

## Last Verified

## Summary
真人守秘人辅助模式需要多台设备同玩一局，而现有游戏是纯前端单机程序，规则引擎、AI 调用与存档都在浏览器里。
决定：新增一个只做中转的 Node.js 服务程序（线下走热点 / 同一 Wi-Fi，线上走 Tailscale），由守秘人浏览器继续结算一切，
并在发出前按玩家过滤内容，服务程序按收件人投递、不理解规则。

## Context

### Problem Statement
作者确认要做真人守秘人辅助模式：守秘人与多名玩家各用自己的设备参加同一局，需要多人同步、暗骰（数值仅开发者账号可见）、
按人可见的线索 / 地图 / 内容限制、共享战斗面板与固定团战役。现有代码没有任何网络同步：`BroadcastChannel` 只用于同一浏览器
多个标签页之间的存档通知，"多人模式"指一名玩家操控多名调查员。联机的拓扑与信任边界决定了之后 15 个系统怎么设计，必须先定。

### Constraints
- **以自用为主**（作者确认），不愿为线上游玩租用或维护服务器；预算接近零。
- **线下要能用**：作者希望线下用热点等本地方式开局。
- **规则引擎深度依赖浏览器页面**：状态挂在 `window.CoCState`，组件为 Vue；把引擎搬到服务端运行风险高、工作量大。
- **AI 调用在浏览器中**：DeepSeek 密钥由用户在浏览器内填写；R30 起 AI 接口只允许 https（本机除外）。
- **Service Worker 需要安全上下文**：通过 `http://局域网IP` 访问时浏览器不会启用离线缓存。
- **浏览器无法做蓝牙主机**，也不能在两台浏览器之间用蓝牙传数据。

### Requirements
- 线下（热点 / 同一 Wi-Fi）与线上用**同一套代码**。
- 暗骰数值、别人的私有线索、触发个人内容限制的段落，**不得出现在不该看到的玩家设备上**——不能只靠前端隐藏。
- 守秘人（开发者账号）与游客两种身份。
- 断线重连后能恢复当前局面。
- 不破坏现有单人模式：不联机时游戏照旧在单台浏览器离线运行。

## Decision

新增一个**中转服务程序**（Node.js），在守秘人的笔记本上运行；守秘人浏览器是唯一的权威。

1. **服务程序职责（只做四件事）**：托管 `src/` 静态页面（https）；管理房间与成员身份；按收件人投递消息；
   保存服务端需要持久化的数据（固定团战役，见系统 28）。持久化数据是**不透明的数据块**，只有 `developer` 身份能读写，
   服务程序不解析其内容。它**不运行规则引擎、不调用 AI、不解析游戏内容**。
2. **守秘人浏览器是权威**：规则结算、AI 调用、存档继续在守秘人浏览器中运行（即现有单机代码）。
   玩家的行动作为"请求"发给守秘人浏览器，结算结果由守秘人浏览器发出。
3. **发出前按人过滤**：守秘人浏览器为每个收件人分别生成内容——开发者账号收到完整数据，游客收到删减版
   （例如暗骰只含"守秘人进行了一次暗骰"）。服务程序只把每份消息投递给指定收件人。
4. **两种连接方式，同一程序**：
   - 线下：守秘人笔记本开热点或连同一 Wi-Fi，玩家浏览器访问局域网地址。**证书的目的是保证能玩，而不是限制谁能玩**（作者决定），
     服务程序同时提供三档连接，玩家用哪一档都能进房间、正常游戏：

     | 档位 | 地址 | 玩家需要做什么 | 差别 |
     |---|---|---|---|
     | A. mkcert 证书 | `https://<局域网IP>:<https端口>` | 在手机上安装并信任 mkcert 根证书 | 体验最完整：离线缓存（Service Worker）、剪贴板可用 |
     | B. 自签证书 | 同上（未装根证书时即为此档） | 浏览器提示证书不安全时点"继续访问" | 能玩；无离线缓存，复制按钮改用兼容写法 |
     | C. 普通 http | `http://<局域网IP>:<http端口>` | 无 | 能玩；无离线缓存；热点内流量不加密 |

     服务程序启动时自动生成自签证书（若已配置 mkcert 证书则优先使用），并同时监听 https 与 http 端口，打印三档地址供守秘人分享。
     玩家页面检测到非安全上下文（`window.isSecureContext === false`）时只给一行提示"离线缓存不可用，联机游戏不受影响"，不阻止进入。
     玩家端不调用 AI、不需要离线缓存，所以 B、C 两档不影响游戏本身；守秘人始终走 `http://localhost:8080`，不受档位影响。
   - 线上：守秘人与玩家加入同一个 Tailscale 网络，服务程序通过 `tailscale serve` 提供 https 地址。
   - **守秘人固定从 `http://localhost:8080` 打开页面**（服务程序在本机该地址同样提供页面）。浏览器把存档（IndexedDB）、
     AI 密钥与模组列表（localStorage）按"协议 + 主机 + 端口"隔离；现有启动方式 `python -m http.server 8080` 正是这个地址，
     所以守秘人的旧存档、战役账本与密钥无需迁移即可继续使用。`localhost` 属于安全上下文，Service Worker 与"AI 接口仅 https（本机除外）"照常生效。
     玩家只使用局域网 / Tailscale 地址，不需要旧数据。若守秘人此前用过其他地址，用现有的存档导出 / 导入（`exportGame` / `importGame`）一次性迁移。
5. **升级路径**：将来需要玩家免装客户端或守秘人离线时查看战役，把同一个服务程序部署到小型云服务器（Caddy 自动 https），代码不变。

### Key Interfaces

传输：WebSocket（玩家端 `wss://`；守秘人本机 `ws://localhost`），每条消息一个 JSON 信封。完整字段由系统 17 的设计文档定义，本 ADR 固定以下约束：

```js
// 信封（所有消息）
{
  v: 1,                    // 协议版本
  room: 'ABCD12',          // 房间号
  epoch: 'k7f3…',          // 守秘人浏览器每次加载页面生成的新纪元号
  from: 'keeper' | '<memberId>',   // 服务程序按连接身份覆盖，客户端填写的值无效
  to: 'all' | 'keeper' | ['<memberId>', ...],   // 收件人；服务程序只按此字段投递
  kind: 'state' | 'event' | 'request' | 'system',
  dseq: 87,                // 服务程序在投递时为每名收件人分配的递增序号（每人各自连续）
  body: { ... }            // 服务程序不读取
}
```

- **身份**：服务程序在创建房间时生成两种随机凭据（至少 128 位）：**房间密钥**（只给守秘人）与**邀请码**。
  凭房间密钥加入的成员角色为 `developer`，凭邀请码加入的为 `guest`。**第一个凭房间密钥加入的连接成为守秘人**（`memberId: 'keeper'`），
  之后凭密钥加入的都是普通开发者账号；守秘人断线期间，其他开发者凭密钥加入**不得顶替守秘人**，守秘人只能凭自己的成员令牌重连。
  加入成功后服务程序发给该客户端一个成员令牌，
  客户端保存它用于重连；开发者账号可以重新生成邀请码（旧邀请码立即失效）并移除成员（吊销其令牌）。
- **以连接身份为准**：服务程序**按 WebSocket 连接加入时获得的身份覆盖 `from`**，并据此校验：
  `kind: 'state' | 'event'` 只接受守秘人连接发出；`guest` 只能发 `kind: 'request'` 且 `to` 只能是 `'keeper'`；
  不符合的消息直接丢弃并记录。
- **`to: 'all'` 的限制**：**只**用于 `kind: 'system'`（如成员上下线、投票开始与结束、房间公告）。服务程序不读 body，只能按 `kind` 判断，因此规则就以 `kind` 为准。
  叙述、检定结果、线索等内容一律按收件人逐个发送，并只能由守秘人浏览器中的**唯一过滤出口函数**产生。
- **玩家之间的出示与分享**：玩家不能直接发消息给其他玩家。出示线索、分享已探索地图等，都以 `request` 发给守秘人浏览器，
  由它结算并按收件人分别发出。
- **重连（补发责任方：服务程序）**：服务程序为每名成员缓存最近已投递的消息（已过滤，按收件人存放，不读 body）。
  客户端重连时上报 `epoch` 与最后收到的 `dseq`：
  - `epoch` 相同且缓存仍覆盖缺口 → 服务程序直接补发缺失的消息；
  - `epoch` 不同（守秘人浏览器刷新过）或缓存已不覆盖 → 服务程序请守秘人浏览器为该成员生成一份可见快照。
  守秘人浏览器刷新后生成新 `epoch`，所有客户端据此请求快照，因此守秘人端不需要持久化计数器。
  `dseq` 由服务程序按收件人分配，每名客户端看到的序号连续，跳号即表示丢包。

### Implementation Guidelines

- 服务程序 **must never** 运行规则引擎、调用 AI 或解析 `body`；它是中转，不是裁判。
- 守秘人浏览器 **must** 在发出前完成按人过滤；**must never** 先发完整数据、再指望游客前端隐藏。
- 发给游客的消息 **must never** 含暗骰数值、他人私有线索、守秘人笔记或触发该游客个人内容限制的原文。
- 玩家浏览器 **must never** 直接改动权威状态；只能发 `request`，由守秘人浏览器结算后回传。
- 单人离线模式 **must** 保持可用：未连接房间时，所有代码路径与现有行为一致。
- 服务程序对守秘人本机只在 `http://localhost:8080` 提供页面，**must never** 让守秘人改用局域网或 Tailscale 地址打开（否则看不到旧存档与密钥）。
- 服务程序 **must** 以连接身份覆盖信封的 `from`，**must never** 信任客户端填写的 `from`。
- 服务程序的静态托管 **must** 为 `.mjs` / `.js` 返回 `text/javascript`（以及 `.css`、`.json`、`.svg` 等的正确 `Content-Type`）；缺少时浏览器拒绝加载 ES 模块，页面完全打不开（原型实测）。
- 守秘人浏览器 **must** 通过唯一的过滤出口函数产生全部 `state` / `event` 消息；`to: 'all'` **must** 只用于 `kind: 'system'`，服务程序拒绝其他组合。
- 服务程序 **must** 同时提供 mkcert / 自签 https 与普通 http 三档连接；**must never** 因证书不受信任或非 https 而拒绝玩家加入。
- 玩家端代码 **must** 在非安全上下文中正常运行：依赖安全上下文的接口（Service Worker、`navigator.clipboard` 等）必须先检测再用，并有降级写法。
- 服务程序代码放在仓库新目录 `server/`，不放进 `src/`，避免被 Service Worker 预缓存与浏览器加载。

## Alternatives Considered

### Alternative 1: 服务端权威（规则引擎搬到 Node.js）
- **Description**：服务端运行规则引擎与 AI，所有客户端都只是显示端。
- **Pros**：作弊与泄露的面最小；守秘人也只是一个客户端，可以中途换人。
- **Cons**：引擎深度依赖 `window.CoCState` 与 Vue 组件，搬迁需要大规模重构；AI 密钥要放到服务端；线下需要笔记本跑完整引擎。
- **Rejection Reason**：工作量与回归风险远超自用阶段的收益；中转 + 守秘人权威已能满足"游客收不到隐藏数据"。

### Alternative 2: 浏览器之间点对点（WebRTC）
- **Description**：守秘人浏览器与玩家浏览器直接建立 WebRTC 数据通道。
- **Pros**：几乎不需要服务程序；延迟低。
- **Cons**：建立连接仍需信令服务；跨网络时常需要 TURN 中继；固定团战役没有地方持久化；手机后台断连处理复杂。
- **Rejection Reason**：仍需要一个服务程序，却多了 NAT 穿透的复杂度。

### Alternative 3: 托管实时服务（Cloudflare Durable Objects、Supabase 等）
- **Description**：使用第三方实时后端做房间与同步。
- **Pros**：不用自己运维；天然在公网可达。
- **Cons**：要按其接口改写；线下热点模式无法使用同一套代码；依赖外部账号与额度。
- **Rejection Reason**：违反"线下线上同一套代码"的要求。

### Alternative 4: 蓝牙
- **Description**：设备之间通过蓝牙直连。
- **Rejection Reason**：浏览器网页不能充当蓝牙主机，也不能在两台浏览器之间用蓝牙传数据；只能做原生 App。

## Consequences

### Positive
- 现有规则引擎、AI 调用与存档代码基本不用搬动，联机是在其外面加一层。
- 线下与线上同一套代码；线上用 Tailscale 不需要租服务器。
- 游客设备从源头收不到隐藏数据，暗骰与内容限制的保密不依赖前端。
- 服务程序很小、无游戏逻辑，容易测试与替换。

### Negative
- 守秘人笔记本必须开着，守秘人掉线则整局暂停（所有结算都在它那里）。
- 守秘人浏览器要为每名玩家分别生成内容，计算与带宽随人数线性增长。
- 线上每名玩家要安装 Tailscale 客户端并接受邀请。
- 新增一个需要维护的 Node.js 程序与本地证书流程。
- 开发者账号能看到全部数据，信任模型假设开发者账号都是守秘人一方。
- 计时与计票类功能（如暂停投票，系统 27）由守秘人浏览器执行、以其时钟为准。守秘人没有一票否决权是规则层面的约定，
  技术上守秘人浏览器仍是唯一权威；以自用为主时接受这一点。守秘人掉线时整局本就暂停，进行中的投票随之冻结，重连后继续计时。
- 固定团战役暂时只存在守秘人笔记本的服务程序里；换另一名成员当守秘人时，需用存档导出 / 导入搬过去，正式方案留给系统 28 的 ADR。

## Risks
- **漏过滤导致泄露**：某条新加的消息忘了按人过滤。缓解：过滤集中在一个出口函数；为"游客快照不含暗骰数值 / 他人私有线索"写自动化测试，纳入 `ci:smoke`。
- **局域网证书在手机上不被信任**：缓解：不再作为门槛，玩家可降到自签 https 或普通 http 档继续游戏（见决定 4 的三档表）。
- **http 档流量不加密**：同一热点内的其他设备理论上能嗅探到别人的消息（包括发给开发者账号的暗骰数值）。缓解：自用、熟人热点下接受；
  开发者账号建议用 A 档或在守秘人本机登录；在意时改用 A 档或 Tailscale（Tailscale 自带加密）。
- **非安全上下文下的静默失败**：现有 `src/js/views/story_view.mjs` 的"复制结局回放"在没有 `navigator.clipboard` 时仍提示"已复制"。缓解：实现联机时把这类调用改为检测 + 降级（`chat_export.mjs` 已有可复用的降级写法）。
- **身份伪造**：客户端伪造 `from` 冒充守秘人。缓解：服务程序以连接身份覆盖 `from` 并校验 `kind` / `to`；为"游客发出 `state` 被丢弃"写自动化测试。
- **守秘人从错误地址打开**：用局域网或 Tailscale 地址打开会看不到旧存档与密钥。缓解：服务程序启动时打印守秘人专用地址 `http://localhost:8080`；守秘人页面检测到非 localhost 时提示。
- **守秘人浏览器休眠或刷新**：手机或笔记本休眠会断开所有人。缓解：守秘人端使用笔记本并提示保持唤醒；重连时由守秘人浏览器从存档恢复并补发快照。
- **状态体量**：完整快照可能较大（剧本、线索、日志）。缓解：首次加入发快照，之后只发增量；消息大小在系统 17 设计时定上限。

## Performance Implications
- **CPU**：守秘人浏览器每次广播需为 N 名玩家各生成一份过滤后的内容；N ≤ 6 的跑团规模下可忽略。
- **Memory**：服务程序为每名成员缓存最近已投递的消息用于补发（条数上限由系统 17 设计确定），内存占用很小。
- **Load Time**：首次加入需下载完整快照；局域网下可忽略，Tailscale 下取决于网络。
- **Network**：跑团是低频事件（每次行动、检定、叙述），远低于实时动作游戏；以增量消息为主。

## Migration Plan
1. 新建 `server/`：静态托管（玩家 https、守秘人 `http://localhost:8080`）+ WebSocket + 房间 / 身份 + 以连接身份覆盖 `from` + 按收件人投递与补发缓存，不改动 `src/`。
   守秘人改用 `server/` 启动后，原 `npm run serve`（同为 8080 端口）不再需要同时运行。
2. 在 `src/js/` 增加联机适配层：未加入房间时完全不生效，保证单人模式与现有测试不受影响。
3. 先做最小原型：两台设备加入同一房间，守秘人发起一次检定，玩家看到结果、游客看不到暗骰数值。
4. 原型通过后再逐个接入系统 19–29。

## Validation Criteria
- 两台设备在热点下、以及在 Tailscale 下，都能加入同一房间并看到同一次检定结果。
- 游客连接发出伪造 `from: 'keeper'` 的 `state` 消息时，其他成员收不到（自动化测试）。
- 守秘人改用服务程序启动后，从 `http://localhost:8080` 打开仍能看到原有存档、战役账本与 AI 密钥。
- 守秘人浏览器刷新后，所有玩家自动收到新快照，界面与守秘人一致。
- 抓取游客设备收到的全部消息，其中不含暗骰数值与他人私有线索（自动化测试）。
- 玩家断线 30 秒后重连，界面恢复到与守秘人一致的局面。
- 未加入房间时，`cd src && npm run ci:smoke` 全部通过，单人模式行为不变。
